## §6.2 gate — CLEARED (spike verdicts)
Native JFR streaming works and **carries full app stacks** (refutes spec:953-955); **M4 TRUE** — native
`ThreadMXBean` is a `com.sun.management.ThreadMXBean`, so native gets the EXACT thread-allocation
cross-check (no JVM/native split); `getCollectionCount()` works — native heap positives publishable.

lateness, per DD-004), **sum `getCollectionCount()` across ALL GC beans** (`System.gc()` moves only one),
and **exclude the JFR consumer's own allocations via `eventThread`**.

## Tasks (one PR)
1. **Disposition on the wire** (`basquin-core` + both producers + driver parse; D1). Disposition is a
   **5th `|` field** on `ResultStore.format`. **Skew behavior pinned HONESTLY (fable issue 2):** the
   frozen old parse (`split("\|",4)` + `"leak".equals(f[3])`, `CoverageGuidedRun.java:1285,1299`) means
   an old driver reading a new (5-field) line silently reads a **leak false-negative** — this is a
   documented, tested consequence (or a version handshake), NOT a claimed impossibility. A new driver
   reading a 4-field line defaults `measured` for Tomcat, **absent-not-assumed** for Quarkus. Both
   directions test-pinned; Tomcat path always publishes `measured`; shipped-jar guard green.
2. **§6.1 filter semantics + driver accounting** (`basquin-quarkus/runtime` + runner): process-global
   in-flight counter (inc `handle`, dec `addEndHandler` on EVERY disposition — native decrement proven
   by PR-4's S3); the **four UNMEASURED producers** — overlap (counter>1), sub-quantum (<1,048,576 B),
   negative, GC-contaminated (**summed-across-all-beans `getCollectionCount()`, sampled AFTER the D5
   pre-measure GC**, fable issue 5a); **stop summing an UNMEASURED hop's heap into `heapKb`**;
   **disconnect flips from drop→publish-with-disposition `disconnected`** (fable issue 7 — kept OUT of
   latency §6.5 and OUT of the crash count §6); **write control-pass state + taint-rate/UNMEASURED/
   disconnect into the summary JSON** (fable issue 3 — Task 4 reads it) with a `failOnMissMajority`-style
   loud fail; thread-leak invariant **suppressed on the reactive path**; D5, D6 probe. Naming: coverage-
   level `unmeasured` stays distinct from the per-sample `UNMEASURED` disposition. Acceptance: §7.3
   overlap + sub-quantum firing controls pass end-to-end (sub-quantum flips from measured-FAIL→PASS);
   A1 GC firing row passes.
3. **JFR heap cross-check — extension-owned (fable issue 1)** (`basquin-quarkus/runtime` + build
   recipe): the RecordingStream consumer ships IN THE EXTENSION (unmodified apps can't provide it),
   `jdk.ObjectAllocationSample` aggregated **whole-run per-route** with **`eventThread` self-exclusion**,
   plus the M4 exact `getThreadAllocatedBytes` cross-check; native build adds
   `-Dquarkus.native.monitoring=jfr`. **Runs as a SEPARATE PASS, not concurrent with §6.1 heap
   windows** (the consumer's ~50 MB self-allocation would inflate GC-contamination taint). Powers
   §7.3's JFR row. Acceptance: alloc route ranks first by sampled bytes on a native heroes/villains cell.
4. **§6.3 watchdog** (`basquin-quarkus` runtime sampler + deployment wiring + threshold; D2/D3): a
   RUNTIME_INIT sampler measuring `Context.runOnContext` scheduling delay, reaching the loop via the
   **boundary-observed context of the in-flight request**, **retaining the last-observed context
   between requests** so D3's diagnostic branch can fire; **the violation id is captured at no-op POST
   time, not measure time** (fable issue 4 — else the block-loop control fails by construction); the
   §6.3 amendment **discloses the post-response-blocking diagnostic gap** (D2 narrows "each loop" to
   the request-attributed loop); `gcBeforeMeasure`'s STW must not self-trip the watchdog (fable issue
   5b — exclude/order it); pinned `basquin.quarkus.watchdog.thresholdMs`. Acceptance: `block-loop`
   control → store entry → finding → driver-visible; thread-leak suppressed; watchdog off ⇒ zero
   boundary overhead.
5. **§7.4 renderer** (`deploy/bench/render_page.py` + a single record writer; D4): per-target invariant
   sets/modes; **the HEAP column AND the event-loop-blocking column are gated on recorded control-pass
   state too** (fable issue 3 — §9 names the heap column), not only taint/UNMEASURED/disconnect;
   with-state → figures, without-state → absent (never 0%); mode-separated coverage; per-target native
   notes. **One shared record writer** (a local emitter; `collect.py` and it must not drift — pin a
   schema check, fable issue 8); the bench manifest records compose-healthcheck-disable + gcBeforeMeasure
   on/off. Parallelizable with 2/3/4 once the D1/D4 record schema is fixed. Acceptance: the gate provably
   closes.
6. **Phase-2 control run + 2×2 rows + remaining docs**: §7.3's full table on the real heroes/villains,
   rows derived from committed records; THIRD-PARTY-APPS/ARCHITECTURE/ROADMAP updates (incl. the stale
   PR-4/#108/#109/#110 roadmap rows). Acceptance: every published invariant column has a passing control.
