# DD-045 items 4-6 — design: enforce what can be enforced, and say plainly what cannot

2026-08-04. Design only — nothing here is implemented. Item texts: `TODO.md`, the `## DD-045`
section, entries 4 ("a \"what depended on this?\" pre-commit pass"), 5 ("stop restating derived
numbers in prose"), and 6 ("an agent completion contract"); fuller rationale in `docs/ROADMAP.md`
under "Start here next". Citations here are by content, path, function name, or row key — never by
`file:line`, and never by a branch SHA: items 0-3 merged to main as squash commits (`4efd7de`,
`28b0698`, `e7137a4` — the branch-side SHAs are already unreachable from any surviving ref, which
is itself a finding this design turns into a check). Every figure is derived from a named CI run
or a command stated in the Appendix, per the standing derive-numbers rule.

**Verdicts up front.**

| Item | Mechanically enforceable? | One line |
|---|---|---|
| 4 | **Partly — at PR/push time in CI, not at pre-commit.** Three concrete checks: removed-path cross-reference, commit-SHA reachability, harness row-label coverage. The "mirror image" (open debt vs. code) stays a convention. | Build the three checks; the current tree already fails the SHA one — 22 checker findings (`FAILED UNREACHABLE COMMIT`) plus 3 disclosed, not the 26 SHA-token occurrences quantified below (checker findings and token occurrences are different units). |
| 5 | **No.** Its enforceable core already shipped inside item 1's carried-value machinery; the remainder (unit identity) is semantic and no extractor can adjudicate it. | Build nothing; close the item as covered-plus-convention. |
| 6 | **Split.** "Partial evidence is never committed" is CI-enforceable on tracked evidence. "A report is accepted only with pasted verification output" is enforceable as a local validator (and optionally a harness hook), and is otherwise convention — said honestly. | Build the evidence-completeness gate and the report-form validator; write the contract next to the tools, not in a standalone ritual doc. |

The central admission this design is built around: items 0-3 guard tracked content, so CI could
enforce them. Items 4-6 partly do not. Where the honest answer is "this is a convention", this
design says so and names the habit, instead of dressing a habit up as a mechanism. A convention
backed by one cheap mechanical command (run this script before accepting) decays far slower than
a convention backed by prose alone — that is the design principle for the unenforceable parts.

## What items 0-3 already cover — do not build a second mechanism

Flagged first so nothing below rebuilds a closed gap:

- **A removed path still cited in prose or `#`-comments** — item 1. `scripts/check-citations.py`
  is whole-tree, so the same push that deletes a file turns every prose/comment citation of it
  into a `DEAD PATH` finding. Item 4 must not re-scan that corpus; its increment is *code* lines
  (the script scans only `#`-comments of `*.sh` and workflow files, and no `.gradle`/`.py`/
  `.java`/`.json` at all — its docstring's "Consciously EXCLUDED" list) plus fenced code blocks
  in markdown, which item 1 deliberately skips.
- **A removed or renamed harness row label** — item 3. `scripts/verify-dd043-pr3-rows.sh` pins
  expected FAIL/PASS rows by exact label, so a label that vanishes from the harness fails the
  rows meta-job at its next run. Only the *added*-label direction is open (its own comment above
  `GREEN_RUN_LABELS` records that residual, deferred to this item). Item 4C below closes it.
- **Evidence regeneration staling citations in bulk** — item 2. Citations routed through
  `bench-results/RUN-OF-RECORD/` survive supersession; item 4 adds nothing there.
- **A derived figure restated in prose beside a citation** — item 1's `CARRIED VALUE` and
  circular-corroboration checks, plus its counted not-examined classes. This is most of item 5;
  see that section.
- **A committed doc citing a gitignored agent artifact** — item 1's gitignored-path `DEAD PATH`
  class (the `agents.md` catch). Item 6's gap is only text that never reaches the repo.

## Item 4 — "what depended on this?"

**Enforcement point, stated precisely.** A true pre-commit hook is not buildable here: git hooks
do not clone, and this repo's own item-3 design already rejected a hook-based mechanism as
"unenforceable across clones and agents". The enforceable point is **CI at pull_request/push
time** — after the commit exists, before it merges — plus the same script runnable locally as
the (conventional) pre-commit pass. Since only the human merges, and merges go through PRs, a
PR-time red is enforcement in every path that matters. What stays convention: running it before
committing (the script makes that a one-liner), and the "mirror image" sweep (4D).

### 4A — removed-path cross-reference (diff-derived removal set × whole-tree grep)

**Mechanism.** A new script — `scripts/check-removed-deps.py` (name negotiable; not in the tree
yet) — that:

1. Computes the removal set: `git diff --name-status --find-renames <base>...<head>` filtered to
   `D` rows and the *old* names of `R` rows. In CI on `pull_request`, base is the PR base ref
   (checkout with `fetch-depth: 0`); on `push`, `github.event.before`..`after`, skipping with a
   printed, counted notice when `before` is the zero SHA (new branch) — a disclosed gap, not a
   silent one. Locally, `--staged` diffs the index against HEAD: that invocation *is* the
   pre-commit pass the TODO item asks for.
2. For each removed path, runs `git grep -nF -- "<path>"` across **all** tracked files at head —
   code included, precisely the corpus item 1 excludes. A hit is a surviving dependent → FAIL,
   unless (a) the hit line ±1 discloses the absence (reuse `NEG_RE` by importing it from
   `scripts/check-citations.py` — one regex, not a second copy; the checker's own
   `tracked_or_pointer()` history shows what two drifting copies of one rule cost), or (b) an
   allowlist entry in `scripts/check-citations-allowlist.txt` (new `removed-ok` kind, reason
   mandatory) exempts it.
3. Prints every hit with file:line, and exits nonzero on any non-exempt hit.

Full-path fixed-string matching only — no basename matching (a deleted `README.md` would light up
the whole tree). Consequence, disclosed: a dependent that references the file by basename alone
is not caught.

**Why this is worth having when item 1 exists.** The gap is real and present today:
`scripts/verify-dd043-pr3.sh`'s `jvm` stage reads
`local bs="bench-results/dd043-pr3-restvillains-2026-07-26/build.sh"` on a code line — invisible
to item 1's comment-only scan. Deleting that evidence directory (already listed in `TODO.md`'s
"DD-043 PR-3 follow-ups" as a break-the-day-it-is-pruned hazard) would merge green today.

**Failure demonstration (required before acceptance).** In a scratch worktree: `git rm -r` the
`dd043-pr3-restvillains` evidence directory, commit, run the checker over that range — it must go
red naming the harness's `local bs=` line. Restore; green. Control: remove a file nothing
references; the checker must stay green (no false positive on mere removal).

**Cost, derived.** One `git grep -nF` probe over the 851 tracked files measured 0.36 s locally
(Appendix); the removal set is empty on most pushes, so the standing cost is ~0. Runs as a step
appended to the `citation-integrity` job, whose entire wall-clock on the run of record for CI
timings was 8 s (Appendix); `fetch-depth: 0` over this repo's 252-commit history (both figures:
Appendix commands) adds seconds at most. First CI run confirms the delta; the CI figure decides.

### 4B — commit-SHA reachability (whole-tree, inside the citation gate)

**The defect class, quantified on today's tree.** This repo squash-merges. A squash merge makes
every branch-side SHA unreachable the moment the branch is pruned — and pruning after merge is
the documented post-merge routine. The Appendix classifier finds **17 distinct** letter-bearing
SHA tokens in `TODO.md` + `docs/ROADMAP.md` (**26 occurrences**) that resolve only via
not-yet-pruned local branches — among them the original-guard commit and all four supersession
commits whose *messages* `TODO.md` cites as the source of its repointing counts. After pruning,
every one is a citation to nothing, on a fresh clone or anywhere else. `scripts/check-citations.py`
cannot see this: it resolves paths and line content, and its docstring deliberately excludes git
hashes as a *value* shape (that exclusion was about hashes-as-quoted-figures and remains
correct). Reachability is a different question, and it is mechanically decidable.

**Mechanism.** Extend `scripts/check-citations.py` with one new token class, keeping its
disposition-ledger discipline (every parsed token lands in exactly one bucket; the sum is
asserted; exit 2 on imbalance):

- **Parse:** backticked or bold hex tokens, 7-40 chars, at least one `[a-f]` AND at least one
  digit (drops English hex-words like "defaced" and all-digit run IDs/dates). Bare-prose hex is
  *not* parsed — counted per class as not-examined, the same printed-blind-spot treatment the
  value checker gives short numbers.
- **Resolve:** prefix-match against `git rev-list origin/main` (measured 0.5 s, Appendix), built
  once per run. Dispositions: `verified (reachable from origin/main)`; `FAILED UNREACHABLE
  COMMIT` (matches nothing there — a branch-only or foreign SHA in a live doc);
  `allowlisted` via a new `sha <prefix> <reason>` allowlist kind (upstream-repo SHAs: the
  Appendix classifier shows a bucket of tokens that are other repos' commits, each needing one
  reasoned entry); `disclosed` when the ±1-line window says the commit is gone (the existing
  `NEG_RE` path); `historical (bench-results evidence)` — counted, never failed — for citing
  files under `bench-results/`: an evidence README naming the commit it *ran against* is a record
  of a past run, not a live claim, exactly the rationale the docstring already applies to
  captured `*.txt`. The run of record's own `Commit:` line names its (now branch-only) SHA and
  is frozen evidence; it lands in this bucket by design.
- **Degrade honestly:** if `origin/main` is not resolvable locally (offline clone), the whole
  class becomes a counted `UNCHECKED — no baseline ref` bucket, never a silent pass. In CI the
  job gets `fetch-depth: 0`, so the baseline always exists there.

**Migration (the check fails first — that is the point).** Landing 4B turns the current tree red:
the checker itself reports 22 `FAILED UNREACHABLE COMMIT` findings plus 3 disclosed absences,
`exit=1` (a different unit from the 26 SHA-token occurrences the Appendix classifier counts below
— that classifier counts raw token occurrences across two files by its own shell pipeline; this is
how many times *the checker* fails). The same PR must resolve every occurrence, by class: (i) claims that survive on main →
repoint to the squash-merge SHA (`4efd7de`, `28b0698`, `e7137a4`, `b32b394` for the recent ones);
(ii) claims about branch-side history that squashing destroyed — above all `TODO.md`'s
supersession-count sentences, which cite counts "read out of that commit's own message" for
commits whose messages will not exist — reword to carry the disclosure that the derivation
predates the squash and is no longer re-runnable, or re-derive from what main retains; (iii)
provenance chains better served by content (the guard-history paragraph in `docs/ROADMAP.md`
already tells the reader the code's own running count is the authority — finish that thought by
removing the per-commit hex). `docs/superpowers/plans/` is already `frozen` in the allowlist, so
the plan-file occurrences cost nothing.

**Going forward — stamp the tree, not only the commit.** Squash merges preserve the *tree*:
verified 2026-08-04, `git rev-parse 'e7137a4^{tree}'` equals the tree hash of the then-current
branch head (that head's SHA is deliberately not written here — this very rule). Add one line to
`scripts/verify-dd043-pr3.sh`'s RESULTS.md header: `Tree:` `git rev-parse 'HEAD^{tree}'`. A
future run of record made on a branch then stays verifiable against main after the squash+prune,
by tree hash, forever. Two-line harness edit; the rows meta-job (whose path filter includes the
harness) runs on it as usual; no row label changes, so no scenario changes.

**Failure demonstration.** Pre-migration, the first run on the current tree *is* the
demonstration — the same "the gate immediately found what the hand-check missed" shape item 1
had on its first corpus. Post-migration: point a scratch doc at any known branch-only SHA →
red; at `e7137a4` → green; break `origin/main` resolution → the counted UNCHECKED bucket
appears rather than a pass.

**Cost, derived.** `git rev-list origin/main` at 0.5 s plus set lookups, inside a script that
completes in 0.97 s locally today (Appendix), in a CI job measured at 8 s. The one-time
migration is the real cost: 26 occurrences across two files, plus one allowlist entry per
upstream SHA.

### 4C — harness row-label coverage (closing item 3's declared residual FOR THE `unit`/`jar`/`guards` stages)

**The gap, in item 3's own words:** the comment above `GREEN_RUN_LABELS` in
`scripts/verify-dd043-pr3-rows.sh` — a label with no scenario is a meta-run failure, "computed at
the end from the scenario table itself, never by parsing the harness's bash". So a harness row
*added* without a scenario is invisible to the meta-check: the label is in neither the table nor
`GREEN_RUN_LABELS`, and nothing compares either against what the harness actually emits.
`GREEN_RUN_LABELS` itself only ever declares labels for the `unit`/`jar`/`guards` stages — the
ones a green `unit jar guards` run produces — so this check can only close the gap for those
three; a row added to `jvm` or `native` stays open, disclosed below, not silently swept in.

**Mechanism — read the run's output, not the script's text.** The `verify-dd043-pr3` job in
`.github/workflows/ci.yml` already produces a fresh green `RESULTS.md` on every matching push,
scoped to `unit jar guards` (the job never runs `jvm`/`native` — docker, 15+ minutes, manual-only).
Append one step (guarded `if: success()`, since only a green run's row set equals the green-run
label inventory): extract the row keys AND the `Stages run:` header line from the new run
directory's `RESULTS.md`, extract the `GREEN_RUN_LABELS` list from
`scripts/verify-dd043-pr3-rows.sh` (a literal, marked Python list — read as data between its
brackets, not by executing anything), partition the observed labels by stage and
exclude-and-count any stage not in {`unit`,`jar`,`guards`} (so a full/`all`-stage RESULTS.md —
e.g. a promoted run of record — does not false-fail on its own `jvm:*`/`native:*` rows), and
require set equality on what remains. Observed-but-undeclared → "new harness row `X` has no kill
scenario" → red. Declared-but-unobserved → red (redundant with the rows job's own unmatched-label
failure, and the redundancy is disclosed, not hidden — the two jobs have different path filters,
and this one is the broader). This honors the item-3 design's refusal to parse the harness's bash:
the label inventory comes from the harness's *artifact*.

**Disclosed residual — not this check's scope.** A row added to the `jvm` or `native` stage has
no kill scenario in `GREEN_RUN_LABELS` either, and this check cannot see it: those two stages
never run in the `verify-dd043-pr3` CI job (docker, 15+ minutes; manual-only, per the harness's
own header), so their RESULTS.md never reaches this checker. Closing that half would mean either
running `jvm`/`native` in CI (the cost item 0 already declined) or a second, manually-invoked
check with no CI trigger to guard it — left open, named here rather than claimed closed.

**Failure demonstration.** Scratch worktree: add a trivially-true `ok "jar:extra-row" ...` row to
the harness copy, run its `jar` stage, run the comparison → red on the undeclared label. Second
direction: delete one label from a copy of `GREEN_RUN_LABELS`, compare against an unmodified green
run → red. Third, the exclusion path: run the comparison against a full (`all`-stage) RESULTS.md
— its `jvm:*`/`native:*` rows are excluded and counted, not reported as findings, and the in-scope
pairing still resolves green. Unmodified both sides → green.

**Cost, derived.** Sub-second text extraction appended to a job measured at 2 m 55 s (Appendix).

### 4D — the mirror image: resolving open debt against the code. Convention, and said so.

Round 9's sweep (all `- [ ]` entries checked against the tree; ten were already satisfied) is the
model, and it does not mechanize. The path-shaped half of every debt entry is *already* checked —
`TODO.md` is in item 1's corpus, so an entry citing a dead path fails today. The rest — "X was
never done", "Y has no test" — has an unresolvable direction ambiguity: an entry about something
to *build* legitimately names things that do not exist, and an entry about something *broken*
names things that do; no grep distinguishes them, and a predicate-per-entry DSL would be a second
hand-maintained mirror that itself drifts (see item 5's reasoning — same shape). What this design
prescribes instead: (a) keep the TODO item's own writing rule — debt entries name a symbol, file,
or workflow step, so the sweep is cheap; (b) run the sweep as a recurring dispatched task whose
report is subject to item 6's contract (pasted `git grep` output per resolved entry), roughly
once per DD-thread close-out. That is a habit. It is written down here as one, not as a
mechanism.

### Item 4 — not worth building

- **A git pre-commit hook.** Hooks do not clone; the item-3 design already rejected a hook
  mechanism on these grounds. The same script invocable as `--staged` gives the local pass
  without pretending it is enforced.
- **Parsing the harness's bash to enumerate labels** — rejected precedent in the item-3 design;
  4C's run-output diff replaces it outright.
- **A general removed-*claim* tracker.** Claims are not mechanically enumerable; that half of the
  item text stays with review and the 4D sweep.
- **A `- [ ]` auto-resolver / open-while predicate DSL** — direction ambiguity above; constant
  triage; nobody maintains per-entry predicates.
- **Keeping pruned SHAs resolvable via tags or git-notes.** It would make the 26 citations
  "resolve" to history that no surviving branch contains — laundering a dead reference into a
  live-looking one, the exact move the citation audit refused when it left STALE-BY-REFACTOR
  citations unrepointed.
- **Scanning bare-prose or all-digit hex** — indistinguishable from run IDs, dates, and byte
  counts; counted as a not-examined class instead, the value checker's own pattern.

## Item 5 — derived numbers in prose. Recommendation: build nothing; close as covered.

This is the item that is not worth building as scoped, and the honest reason is that its
enforceable core **already shipped** inside item 1:

- A strong-shaped figure (cost CSV, 4+-digit number, thousands-separated, UTC stamp) restated in
  backticks, bold, attribute quotes, or bare on a citation line is checked against the cited
  files — the `CARRIED VALUE` and `STALE LINE` classes.
- A figure "verified" only by another hand-typed prose figure is caught by the
  circular-corroboration class (`values backed ONLY by cited prose .md`).
- Everything the tool does *not* examine — short numbers, digit-bearing spans with no strong
  shape — is counted per class in every run's summary, so the blind spot is a printed number,
  not an unknown.

What remains of item 5 after that is the *unit* problem: round 8's miscount came from documents
counting shapes, throw sites, and methods interchangeably, and the ROADMAP's "Mind the
arithmetic" passage (eight shapes, seven throws, distributed 1/1/3/2) shows why no token-level
check can adjudicate it — the figures are all "correct"; what drifts is *what they count*. A
mechanism here would have to understand referents. The candidates were weighed and all fail the
same way:

- **A unit-annotation format** (`**8** <!-- unit: shapes -->`, or a pinned-count DSL): typed by
  the same hand that typed the number, checkable only for its own presence — a second mirror
  that drifts, adding maintenance without discrimination.
- **Extending the value checker to short numbers**: the tool's own docstring already rules it
  out — "substring-matching a 1-3-digit number against a file is meaningless".
- **An LLM-judge unit reviewer in CI**: a nondeterministic gate; nothing in this thread's house
  style admits a check whose failure cannot be reproduced byte-for-byte.

So item 5 ships as: (1) **nothing mechanical**; (2) the standing rule, already adopted in round 7
and already written in `docs/ROADMAP.md`'s item-5 paragraph — derive in place with the command
shown, or point at one authoritative enumeration, and name the unit when a count stays — kept
there, *not* duplicated into a new doc (a second copy of a rule is the two-copies defect); (3)
the TODO entry closed with this disposition in the same PR that does 4B's migration, since that
PR is already editing the exact `TODO.md`/`docs/ROADMAP.md` regions and a separate PR would
conflict with it. The check on the habit is review plus item 1's counters; this design declines
to pretend otherwise.

## Item 6 — the agent completion contract

Designed against the four observed failures, not the abstract idea:

| Observed failure | What mechanically prevents or catches it |
|---|---|
| ~70 citations "hand-verified accurate"; the gate failed 4 paths on the same file immediately | The contract requires the *tool's pasted output*, not an assertion of diligence: a report whose verification section lacks the checker's own disposition line does not validate (6b). Running the tool is what finds the four paths; the form check makes not-running it visible. |
| A fix "proven" by three exit codes; one run had refused and written no artifact | 6b requires every artifact named in the verification section to exist on disk at validation time; a refused run's missing directory fails the report. 6a fails the same shape at CI if partial evidence is committed anyway. |
| Killed mid-work after reporting success; verification never ran | Nothing can gate a killed session. The contract inverts the order instead: verification artifacts to disk *first*, report last — then a kill leaves artifacts without claims (recoverable) rather than claims without artifacts (poison). The parent treats report-without-artifact as not-done; 6b makes that a one-command check. |
| Wait-loops that cannot distinguish running from finished | Contract clause, convention: every wait must watch a terminal artifact (an `exit=` line, a file that appears), never a process-name poll — this task's own brief carries the standing example of a poll that matches its own waiting shell. Existing machinery (the PR-watch pattern) already does this right; no new tool. |

### 6a — partial evidence never *merges*: an evidence-completeness gate. CI-enforceable.

**Mechanism.** A new script — `scripts/check-evidence-complete.py` (not in the tree yet) — as a
second step in the `citation-integrity` job (whose path filters already carry
`bench-results/**` on both lists, so the guard is reachable for exactly the edits that could
break it). Scope: **machine-produced evidence shapes only**, where "complete" has a definition;
free-form hand-authored evidence READMEs have none, and that boundary is printed
(`N bench-results dirs out of scope for completeness`), not implied:

- every tracked `bench-results/verify-*/` directory must contain a `RESULTS.md` whose header has
  a `Commit:` line (and, once 4B's tree-stamp lands, a `Tree:` line) and whose
  `**P passed, F failed, S skipped**` tally parses **and equals the row count of its own table**
  — a truncated or refused-run directory (the "no RESULTS.md, only git-status.txt" shape that
  the harness's dirty-gate refusal produces, and that one session's false "three exit codes"
  report traced to) fails;
- the `NON-CITABLE` tag must be absent from any tracked `RESULTS.md` — a run stamped
  do-not-cite, committed as evidence, is the definition of partial evidence (override: an
  allowlist entry with a reason, the house pattern);
- every tracked `bench-results/verify-rows-*/` `RESULTS.md`: same rules, plus its
  observed-exit column present;
- every tracked `bench-results/citations-*/` directory must contain `output.txt` and
  `README.md`, with the final disposition line parsing and its buckets summing to its own parsed
  total — re-asserting, on the committed copy, the invariant the tool asserts at runtime;
- the directory `bench-results/RUN-OF-RECORD` names must be one of the verify dirs that passed.

Today's corpus is one verify directory and one citations directory (Appendix), both compliant —
the gate lands with zero grandfathering, and everything else is out-of-scope-and-counted.

**Failure demonstration.** Stage — never committed — a `bench-results/verify-SCRATCH/` dir
holding a log but no `RESULTS.md` → red naming the refused-run shape. Truncate a copy of a tally line so
it disagrees with its table → red. Add `NON-CITABLE` to a scratch copy → red. Unmodified
tree → green. Point a scratch `RUN-OF-RECORD` at the incomplete scratch dir → red.

**Cost, derived.** Parses two directories today; bounded by the same 8 s job; the whole
`scripts/check-citations.py` run over 851 files takes 0.97 s locally (Appendix), and this
script reads
strictly less.

### 6b — the report side: a form validator, plus (optionally) the one hook that reaches reports

**What exists today, per survey of this working copy:** no Stop/SubagentStop/TaskCompleted hooks
in any settings file, repo or user level; no tracked agent definitions; reports live in
`.superpowers/sdd/` (gitignored, local-only), where the task-N naming collision is not
hypothetical — five files sit renamed `STALE-from-prior-session-*` and a prior plan's reports
needed their own archive directory. The pasted-verification *practice* already exists in the
better reports ("Commands run, with real output"); nothing checks for it.

**Mechanism, the enforceable core:** `scripts/check-agent-report.py` (not in the tree yet) —
tracked, so it survives clones and is itself testable in CI. Input: one report file. Checks,
each mapped to a failure above:

1. a verification section containing at least one fenced block with a command line and a
   captured `exit=<N>` line — the repo's `; echo "exit=$?"` idiom (absence → red: "reported
   success, verification never ran" becomes structurally unwritable);
2. a header stamp naming the HEAD SHA the verification ran against; the validator compares it to
   `git rev-parse` output and reds on mismatch — the stale task-N-reuse class, and the standing
   "grep the handoff file for the commit range" rule, automated;
3. every artifact path named in the verification section exists on disk (the refused-run shape:
   claimed artifact absent → red);
4. any tally or exit code asserted in the report's prose must also appear inside a pasted block
   (a prose-only claim → red) — the claims-match-their-check rule in checkable form.

**Its limit, printed in its own output, not buried here: it validates form, never truth.** A
fabricated paste passes. Truth is enforced at the next layer down — the moment evidence is
committed, items 0-3 plus 6a grade the bytes — and by the parent re-running the pasted one-liner
when stakes warrant. A form gate is still worth having for the same reason the citation gate
was: every observed failure was *formless* (no pasted output, no artifact, wrong commit), and
form is what a machine can hold.

**Enforcement wiring, two levels, honestly distinguished:**

- **Convention with a mechanical assist:** the dispatching agent runs the validator on the
  report file before accepting. One command. Still a habit — but "run one command" is the
  smallest habit that exists, and its output is pasteable into the *parent's* own report,
  making the acceptance itself auditable under the same contract.
- **Mechanical, opt-in, this-harness-only:** a `SubagentStop` hook in a new tracked
  `.claude/settings.json` (not in the tree yet) that runs the validator against the finishing
  subagent's report/transcript and returns a blocking decision with the validator's findings as
  the reason when the transcript used mutating tools but the contract marker is absent. Honest
  boundaries, all three stated: it binds only Claude-Code sessions in this checkout whose user
  approved project hooks; it cannot help a killed session (nothing can — the artifact-first
  ordering is the mitigation); hook event names and blocking semantics must be confirmed
  against current harness docs at implementation time, and this is the design's one
  external-behavior dependency. Ship the validator regardless; the hook is a bolt-on that can
  be reverted without touching it.

**Failure demonstration.** Run the validator against one of the existing
`STALE-from-prior-session-*` files in the local gitignored scratch (stamp mismatch → red);
against a fixture report with prose claims and no pasted block → red; against a compliant
fixture → green. For the hook: a deliberately non-compliant trivial subagent (edit a file,
report "done" bare) must be blocked with the validator's reason; a compliant one must complete.

### 6c — the contract text itself. Convention, located where it cannot drift silently.

The normative text lives in the validator's own docstring — the one place that changes in the
same commit as the check, so the claim and its check cannot part (this thread's entire thesis).
`TODO.md`/`docs/ROADMAP.md` item-6 entries get a pointer, not a copy. The clauses, from the
evidence table above: verification before report, artifacts before claims; paste the tool's

### Item 6 — not worth building

- **Truth-verification of reports.** Impossible in general; the honest boundary is form here,
  bytes at the repo gate.
- **Agent-bus message validation.** The bus is local-only and gitignored; GitHub labels are the
  real state machine; validating a channel that exists on one machine enforces nothing durable.
- **Committing agent reports so CI can see them.** It would drag session-scratch into the tree,
  fight the deliberate local-only pattern, and gain little: the *evidence* the reports point at
  is what belongs in `bench-results/`, where items 0-3 and 6a already grade it.
- **A validator for the validator.** The regress stops at a small presence-based script,
  reviewable whole — the same declared stop as the item-3 meta-check.
- **New wait/poll infrastructure.** The terminal-artifact pattern plus existing watch machinery
  suffices; the failure was a habit, and the contract clause names the habit.
